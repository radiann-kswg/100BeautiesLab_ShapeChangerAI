# 形状変化絵（TF）の生成

リポジトリ `100BeautiesLab_ShapeChangerAI` の形状変化パイプラインを、依頼から完成画像まで進める手順。規則と仕様は次の正本にあり、このスキルは進め方を持つ。

| 知りたいこと | 正本（リポジトリのルートから） |
| --- | --- |
| 作業ルール、著作物の扱い、出力と記録 | `AGENTS.md` |
| オプション、出力の構成、コネクタのツール、環境変数 | `src/README.md` |
| 16 形状の番号と寸法 | `--list-modes`（コネクタは `shapechange_list_modes`）。実行のたびにシェーダーから読む |

## 入口

| すること | 入口 |
| --- | --- |
| 一覧と `--dry-run`（課金なし・API キー不要） | リポジトリのルートで `python -m src.pipeline.shape_pipeline …` |
| 生成と改稿（課金あり） | コネクタ `shapechange_*` がつながっていればコネクタ。なければ `.env` に API キーを設定した環境の CLI |

リポジトリもコネクタも手元にないときは、組み立てたコマンドを依頼者に渡す。

## 手順

1. **対象を決める。** 依頼から、キャラクター（バッジ）、形状番号（0〜15）、レイアウト（`single`／`sequence`＝変形前→途中→完了／`five-view`＝五方向図）を読み取る。複数体を 1 枚に描く依頼は `--joint` で、キャラクターごとに形状を決める。
   - 形状語が複数の番号に読めるとき（「立方体」は 0 と 2、「球」は 4 と 5、「円柱」は 6 と 7、「平面」は 9〜12）は、形状の一覧を見せて依頼者に選んでもらう。
   - `--natural`（コネクタは `shapechange_generate_from_natural`）は代表の形状に決めて進むので、読み取った形状を依頼者に伝える。
   - キャラクターは `--list-characters`（コネクタは `shapechange_list_characters`）に出るものから選ぶ。この一覧が AI 利用を許可されたキャラクターの全体。

   完了: 対象が一覧にあり、形状番号とレイアウトが 1 つに決まっている。

2. **生成前に中身を見せる。** 決めた引数に `--dry-run` を付けて実行し、プロンプトと参照画像の一覧を依頼者に示す。出力の `[キャラクター（変形前の姿）]` から髪と瞳の色、耳、尾の本数、衣装を拾い、どれを残せば同じ子だと分かるか、どの部位が形に合わせて変わるかを具体的に添える。生成は課金を伴うので、回数の見込み（5 段階は 1 回の実行で画像生成が最大 7 回ほど、`--quick` は 1 回）も伝える。追加の参照画像（`--ref`）を使う依頼では、先に `AGENTS.md` の「著作物の扱い」で素材を確かめる。

   完了: 依頼者がその内容を見て、生成を承認した。

3. **生成する。** CLI は同じ引数から `--dry-run` を外して実行する。コネクタは `shapechange_generate_character`／`shapechange_generate_joint` でジョブを登録し、`shapechange_job_status` を完了まで確かめる。
   - Stage 2 の画像観察が失敗して確認待ち（コネクタは `awaiting_confirmation`）になったら、理由を依頼者に示し、続行か中止かの回答を待つ。回答を得てから、CLI は表示された確認に、コネクタは `shapechange_answer_reference_warning` に同じ回答を渡す。回答がないときは中止する。

   完了: 完成画像の場所（実行フォルダー名かリンク）を依頼者に渡した。

4. **結果を確かめる。** 完成画像を開いて原設定と見比べる。輪郭が指定の形状か、手順 2 で挙げた特徴が 1 つずつ残っているか、尾の本数が合っているかを見る。検査の指摘は `stage4_correct/analysis_log.json`（コネクタは `shapechange_get_run_logs`）にある。尾の本数の自動カウントは 1〜2 本ずれることがあるので、画像で数える。

   完了: 挙げた特徴の 1 つずつについて、残っているか崩れているかを依頼者に報告した。

5. **直す。** 崩れた点は改稿で直す（`--iterate-from <実行フォルダー名> --revisions "…"`、コネクタは `shapechange_iterate`）。`--revisions` には、変える点と保つ特徴（例: 「表情を笑顔にする; 尾は 7 本のまま」）を並べて書く。改稿は新しい実行フォルダーに保存される。変えた点と確認結果を、ローカルの実行ではそのフォルダーの `notes.md` に、コネクタの実行では依頼者への報告に残す。
